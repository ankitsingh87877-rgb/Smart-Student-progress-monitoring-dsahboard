Problem & Objective

Teachers usually see a struggling student only after an exam has been lost, because marks, attendance and assignments live in separate registers.

Problem statement

Given each student's marks, attendance and assignment results: compute a progress score, rank and flag at-risk students, find the closest suitable peer or mentor, plan study hours, and schedule mentoring without clashes.

Target users: faculty mentors, class coordinators and students.

Constraints & scope

  • Scores normalised to 0–1; distances never negative
  • Study time and mentoring slots are limited
  • Console prototype on synthetic data
  • Excludes real records, machine learning and ERP integration

Success criteria

Most at-risk student ranked firstDijkstra = Floyd–WarshallStudy plan = brute forceSlot count = brute forceMentor round = brute forceMemoization removes repeated work

Industry & Application Overview

Colleges and online platforms use learning analytics and early-warning systems to find students at risk.

Albreiki, Habuza & Zaki (2023)

Turn student records into a graph through a distance-based adjacency matrix and feed topological features to machine learning.

Trask et al. (2024)

Put students, videos and assessments into one heterogeneous graph for online courses.

Gap this project fills

The first approach links students only, needs O(n²) matrix space, depends on a distance threshold and relies on training that is hard to explain. The second does not say what a weak student should do next. This project uses an adjacency list, a documented threshold and plain classical algorithms, and gives actionable outputs: a priority list, a nearest mentor, a study-hour plan and a clash-free mentoring schedule.

Data & Progress Score

Progress score = 0.5 × marks + 0.3 × attendance + 0.2 × assignments. Students below 55 are at risk. Edit the CSV below and press Recompute: every demo on this page updates.

Module 1 · Trees & Heaps binary max-heap · heap sort · AVL

A max-heap ordered by risk (100 − score, ties broken by lower attendance) keeps the most at-risk student on top; insert and remove cost O(log n); heap sort ranks the class in O(n log n). An AVL tree keyed by progress score gives sorted display and range queries in O(log n + k).

Risk ranking (heap sort)

AVL tree range query

Report result: height 4 after 7 rotations on 12 students. On 20,000 synthetic records the AVL height was 17 against an ideal of about 15, and the range query (~8 ms) was only slightly ahead of a list filter (~12 ms), so its advantage appears with larger data or repeated queries.

Module 2 · Graphs adjacency list · BFS · DFS · Dijkstra · Kruskal

Each student is a node; two students share an edge when the Euclidean distance between their normalised (marks, attendance, assignments) vectors is at most the threshold. Space O(V+E), traversals O(V+E), Dijkstra O((V+E) log V), Kruskal O(E log E).

Click a node to select it. Green = mentor candidate (score ≥ 80), red = at-risk.
Mentor table
Traversal & spanning tree

Report result at 0.15: 14 edges, two components (eleven connected students, S10 alone), Kruskal MST of 10 edges and weight 0.915. At 0.20 or higher S10 joins the main cluster. Prim, Bellman–Ford, matrix-chain multiplication and topological sort were studied but not coded, and Floyd–Warshall is used only to cross-check Dijkstra.

Module 5 · Advanced Trees & Heaps design study, not coded

B+ tree

Suits a university-wide student database on disk; linked leaves answer range queries such as "all students scoring 40–60".

Red-black tree

Guaranteed O(log n) updates for a live in-memory dashboard.

Fibonacci heap

Lowers Dijkstra's bound to O(E + V log V) on a very large similarity graph.

Binomial heap

Cheap merging of department-wise priority queues.

Not implemented because a class of a few thousand students shows no practical gain. B-trees were also studied.

Integrated Solution & Validation

The program loads and validates records (LCS flags near-duplicate roll numbers), computes progress scores, ranks with the heap, keeps the AVL tree, builds the similarity graph, finds clusters, mentors and the spanning tree, then plans study hours, slots and the mentor's round. Data handling is separate from the algorithms.

Benchmark on synthetic data

Report (1,500 students, threshold 0.08): 4,607 edges, graph build ~0.30 s, component search 0.004 s, Dijkstra 0.001 s, Kruskal 0.007 s. Building the graph compares every pair of students, O(n²), so it is the bottleneck for very large classes. Times vary by machine, and all data is synthetic, so results show algorithmic correctness, not educational effectiveness.

Benefits, Challenges & Future Work

Expected benefits
  • Explainable priority list for mentors
  • A named peer and a study plan for each at-risk student
  • Mentoring scheduled without clashes

Learning outcomes: choosing the right data structure, analysing time complexity, using DP only where it pays off, validating against independent checks.

Challenges
  • Defining nodes, edges and weights: solved with a normalised distance and a documented threshold
  • Equal risk scores: ties broken by attendance, tests compare keys
  • A loose threshold joins everyone into one cluster
  • Confidential real data: synthetic data and fixed travel times used
Future improvements
  • Anonymised real records; tune threshold and weights with faculty
  • B+ trees, Fibonacci heaps, faster graph building than all-pairs
  • Menu or web interface with a database; prerequisites via topological sort
Conclusion

Trees and heaps, graphs, dynamic programming, and backtracking with branch and bound combine to solve one educational workflow. All thirteen tests pass, including a 26-minute mentor round and a 3-slot schedule that equal their brute-force checks.
